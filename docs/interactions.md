# Wishlist — функціональні інтеракції

**Статус:** усі екрани, рішення прийняті. Очікує апрув перед завданням для промптера.
**Охоплює:** Init, «Мої бажання», «Додати», «Поділитися» + глобальна поведінка.
**Базується на:** [spec.md](spec.md), [style-guide.md](style-guide.md) (Ui).

**Контекст етапу.** Ітерація 1 — один користувач, локальна БД, без авторизації. Усе нижче описує саме її. Місця, де майбутня авторизація (імʼя + імейл, етап 2) вплине на поведінку, позначені як **→ етап 2**.

---

## 0. Глобальна поведінка

### 0.1. Навігація

Чотири екрани, «Мої бажання» — єдиний хаб:

```
Init ──► Мої бажання ──► Додати ──┐
                │  ▲              │
                │  └──────────────┘
                │
                └──► Поділитися ──┐
                   ▲              │
                   └──────────────┘
```

- **Init → Мої бажання** — одноразово, назад повернутись неможливо.
- **Мої бажання → Додати / Поділитися** — кнопками з хедера (desktop) або нижньої панелі (mobile).
- **Назад** із «Додати» і «Поділитися» — кнопка «←» у лівому верхньому куті; апаратна кнопка «назад» / свайп браузера роблять те саме.
- Прямих переходів між «Додати» і «Поділитися» немає.

### 0.2. Персистентність

- Кожна зміна (додавання, «✓», видалення, зміна імені) пишеться в локальну БД **одразу**, без кнопки «зберегти» і без дебаунсу.
- Перезавантаження сторінки відновлює: список бажань, імʼя. **Не** відновлює: активний фільтр (скидається на «Усі»), чернетки форми, відкриті інлайн-підтвердження.
- Якщо локальна БД недоступна (приватний режим, вичерпана квота) — показується інлайн-повідомлення «Не вдалося зберегти» на місці дії; додаток не падає, але зміна не застосовується.

### 0.3. Клавіатура

| Клавіша | Дія |
|---|---|
| `Enter` в текстовому полі | Підтвердити форму, якщо валідна; інакше ігнорується |
| `Esc` | Закрити модалку / скасувати інлайн-підтвердження |
| `Tab` | Стандартний обхід у порядку читання |
| `Space` / `Enter` на кнопці «✓» | Перемкнути «здійснено» |

Фокус завжди видимий — hairline-ring `#e5e5e5`, той самий, що у фокусі інпутів.

### 0.4. Анімації

Єдиний набір тривалостей на весь застосунок: **150мс** (кросфейд контенту), **200мс** (поява/зникнення), **300мс** (переміщення картки в списку). Пом'якшення — `ease-out`. При `prefers-reduced-motion: reduce` усі переходи стають миттєвими, стани зберігаються.

## 1. Екран Init

### 1.1. Поле вводу імені

- Автофокус на полі одразу при показі екрана.
- Ввід обмежений **15 символами** — далі просто не приймається (hard limit), а не показ помилки постфактум.
- Пробіли на початку/кінці обрізаються (`trim`) перед перевіркою довжини і перед збереженням.
- Підказка під полем:
  - 0–2 символи (після trim): «Ще мінімум N символів» — Mid Gray.
  - 3–15 символів: статична підказка «Від 3 до 15 символів». Живого лічильника «N / 15» немає.

### 1.2. Кнопка «Далі»

- Неактивна (приглушення через opacity/тон, не Ember), доки `trim(name).length < 3`.
- Стає активною миттєво, реактивно на кожне натискання клавіші.
- `Enter` = клік по «Далі», якщо кнопка активна; якщо неактивна — ігнорується (без «дрижання» поля чи звуку помилки).

### 1.3. Збереження і перехід

- При кліку: `Profile` створюється з `name`, `userId = "local-user"`, порожнім `email` і зберігається синхронно — перехід без екрана завантаження.
- Перехід — fade, без модалки підтвердження.
- Екран Init більше **ніколи** не показується, поки в локальній БД є профіль — навіть якщо список бажань порожній.
- **→ етап 2:** цей екран стає формою реєстрації — додається поле імейла і валідація формату; логіка імені лишається без змін.

## 2. Екран «Мої бажання»

### 2.1. Хедер

Зверху екрана, в один ряд (desktop) або два (mobile):

- **Імʼя користувача** — клікабельне, відкриває модалку зміни (2.7).
- **Лічильник** «3 бажання · 1 здійснене» — Mid Gray, з коректним відмінюванням (spec.md, 4.1). **Завжди показує загальну кількість**, незалежно від активного фільтра.
- **Кнопки** «Додати» (Primary Filled) і «Поділитися» (Outline).

### 2.2. Фільтр

- Три Badge-контроли: «Усі / Активні / Здійснені». Активний — Solid, решта — Outline.
- Перемикання миттєве, без анімації переходу між наборами (рендериться інша підмножина).
- Вибір **не зберігається**: повернення з «Додати» чи «Поділитися», як і перезавантаження, скидає фільтр на «Усі».
- Цифри в лічильнику при перемиканні **не змінюються** — він рахує весь список, не відфільтрований.

### 2.3. Картка бажання

Вміст: емодзі (або картинка), назва, ціна з валютою, посилання «Подивитися →», кнопка «✓», іконка видалення.

- **Емодзі** — Unicode-глиф, дефолт `🎁`, якщо користувач не вибрав свій і не завантажив картинку.
- **Ціна** — показується тільки якщо задана; формат `₴3 000` (пробіл як роздільник тисяч, символ валюти відповідно до `currency`).
- **«Подивитися →»** — показується тільки якщо є `url`; відкриває посилання в **новій вкладці** (`target="_blank"`, `rel="noopener noreferrer"`). Клік по посиланню не тригерить інші дії картки.
- **Кнопки «✓» і видалення** — на desktop зʼявляються при наведенні на картку (fade 150мс); на mobile видимі завжди.
- **Hover картки** (desktop) — легке підняття тіні, без зміни кольору чи рамки.

### 2.4. Порядок карток і позначення «✓»

**Порядок:** активні зверху, здійснені знизу, без розділювача — суцільний список. Усередині кожної групи — за `createdAt`, **найновіші зверху**.

**Позначення здійсненим:**
1. Клік «✓» → миттєва оптимістична зміна: іконка переходить у Solid-стан.
2. Картка тьмяніє (opacity, 200мс).
3. Картка переміщується в кінець списку плавним reflow (300мс), не перескоком.
4. Лічильник оновлює частину «· N здійснені».

**Оборотність:** повторний клік повертає картку в активні тим самим переходом у зворотному напрямку — на позицію за `createdAt`, **не** на місце, де вона стояла до позначення.

**Взаємодія з фільтром:** якщо активний фільтр «Активні», щойно позначена картка після анімації зникає зі списку (fade + collapse). Це очікувано і не потребує повідомлення.

**Чого немає:** підтвердження, конфетті, звуку. Дія легка й часта — тертя має бути мінімальним.

### 2.5. Видалення

1. Клік по іконці кошика (Ember `#e7000b`) запускає **інлайн-підтвердження прямо на картці**: вміст заміщується текстом «Видалити бажання?» і двома кнопками — «Скасувати» (Outline) і «Видалити» (Ember). Габарити картки не змінюються, контент кросфейдиться (150мс). Модалки й затемнення фону немає.
2. Поки підтвердження відкрите, решта карток лишаються повністю робочими.
3. Відкриття підтвердження на іншій картці автоматично закриває попереднє — одночасно активне лише одне.
4. **«Видалити»** → картка зникає (fade + collapse висоти, 200мс), лічильник і решта списку переставляються без стрибка.
5. **«Скасувати»**, клік поза карткою або `Esc` → контент кросфейдиться назад, дані не змінюються.
6. Видалення **остаточне**, «undo» немає.

### 2.6. Порожні стани

| Ситуація | Текст |
|---|---|
| 0 бажань загалом | «Поки що жодного бажання. Чого тобі хочеться?» + кнопка «Додати» |
| Фільтр «Активні», активних 0 | «Усі бажання здійснені 🎉» |
| Фільтр «Здійснені», здійснених 0 | «Ще жодне бажання не здійснене» |

У другому й третьому випадках фільтр лишається на екрані — щоб було видно, чому список порожній, і можна було перемкнутись назад.

### 2.7. Зміна імені

- Клік по імені в хедері відкриває модалку: заголовок «Змінити імʼя», поле заповнене поточним значенням, автофокус із курсором у кінці, кнопка «Зберегти».
- Валідація ідентична Init (1.1–1.2): `trim`, 3–15 символів, статична підказка, кнопка неактивна поза діапазоном.
- Закриття без збереження — клік поза модалкою, іконка «×» або `Esc`.
- Збереження оновлює `Profile.name` миттєво й закриває модалку; заголовок «Список бажань {імʼя}» підхопить нове значення при наступному відкритті «Поділитися».
- **→ етап 2:** сюди ж додасться імейл і, ймовірно, вихід з акаунта.

### 2.8. Повернення з «Додати» — підсвічування нової картки

- Нова картка зʼявляється **зверху групи активних** (найновіша за `createdAt`).
- Підсвічування — **тоном, не кольором**: фон картки на ~900мс переходить `#ffffff → #f5f5f5` і плавно повертається.
- Якщо картка поза видимою областю — список автоскролиться до неї одночасно з підсвічуванням (`smooth`).
- Фільтр на цей момент уже скинутий на «Усі», тож нова картка гарантовано видима.

## 3. Екран «Додати»

### 3.1. Поле «Що це?» (обовʼязкове)

- Автофокус при відкритті екрана.
- Єдине поле, що впливає на активність кнопки збереження.
- `trim` перед перевіркою: рядок із самих пробілів не вважається заповненим.
- Ліміт довжини — 60 символів (hard limit, як на Init).

### 3.2. Вибір емодзі

- Рядок із 8 популярних: `🎁 📚 ✈️ 🎧 👟 💻 🎮 ☕`.
- Вибраний елемент виділяється hairline-рамкою (radius 18px) — без кольорової заливки.
- Повторний клік по вибраному емодзі **знімає вибір**.
- Якщо на момент збереження нічого не вибрано і картинки немає — записується дефолт `🎁`.
- Вибір емодзі при завантаженій картинці знімає картинку (див. 3.3).

### 3.3. Завантаження картинки

- Зона `dashed hairline`, radius 10px, підпис «Завантажити». Клік відкриває системний файловий діалог; на desktop працює також drag & drop.
- Обмеження: **до 5 МБ**, формати **JPEG / PNG / WebP / GIF**. Перевірка до читання файлу.
- Після вибору — прев'ю (radius 10px) з іконкою «×» для видалення.
- **Взаємовиключність з емодзі:** завантаження картинки знімає вибір емодзі, вибір емодзі прибирає картинку. Активним лишається щось одне; UI показує це явно — неактивний варіант приглушується.
- Файл стискається на клієнті (до ~1200px по довшій стороні) перед записом у локальну БД.
- Помилки — інлайн під зоною, Ember-текстом: «Файл завеликий, максимум 5 МБ» / «Непідтримуваний формат».

### 3.4. Ціна і валюта

- Поле ціни приймає **тільки цифри** — інші символи не вводяться.
- Введене форматується пробілами на льоту: `3000` → `3 000`.
- Валюта — компактний select поруч: **UAH (за замовчуванням)**, PLN, USD, EUR.
- Поля незалежні: можна лишити ціну порожньою (валюта тоді просто не використовується). Якщо ціна задана — валюта записується разом із нею.
- Нуль допустимий (безкоштовне бажання), відʼємні числа неможливі за побудовою.

### 3.5. Посилання

- Поле з плейсхолдером `https://…`.
- При збереженні, якщо протоколу немає, `https://` **додається автоматично**: `rozetka.com.ua` → `https://rozetka.com.ua`.
- Валідація м'яка — перевіряється лише базова схожість на URL. Якщо рядок явно не URL, під полем зʼявляється Ember-підказка «Схоже, це не посилання», але **збереження не блокується** — поле необовʼязкове і не варте тертя.

### 3.6. Кнопка «Додати бажання»

- Неактивна, поки `trim(title)` порожній. Активність перераховується на кожне натискання клавіші.
- `Enter` у будь-якому текстовому полі форми = клік по кнопці, якщо вона активна.
- При кліку: запис створюється з `id`, `userId = "local-user"`, `createdAt = now`, `isDone = false` → перехід на «Мої бажання» → підсвічування нової картки (2.8).
- Повторні кліки під час збереження ігноруються (кнопка блокується до завершення переходу).

### 3.7. Скасування

- Кнопка «←» / «Скасувати» у лівому верхньому куті.
- **Форма порожня** (жодне поле не заповнене) → вихід одразу, без питань.
- **Хоч одне поле заповнене** → інлайн-підтвердження на місці кнопок: «Скасувати додавання? Введене не збережеться» + «Продовжити редагування» (Outline) і «Скасувати» (Ember).
- Те саме підтвердження спрацьовує на `Esc` і на апаратну кнопку «назад».
- Чернетка **не зберігається**: наступне відкриття «Додати» дає чисту форму.

## 4. Екран «Поділитися»

### 4.1. Вміст

- **Банер-шапка** — Confetti Amber `#f59e0b`, radius 24px, текст Ink Black: заголовок «Список бажань {імʼя}» (Geist 600, display) і підпис-лічильник, напр. «2 бажання». Це єдине місце в застосунку з цим кольором.
- **Картки** — спрощені: емодзі/картинка, назва, ціна. Без «Подивитися», без «✓», без видалення. Некликабельні.
- **Здійснені бажання не показуються взагалі** і не враховуються в лічильнику банера.
- Порядок — за `createdAt`, найновіші зверху (як на основному екрані).

### 4.2. Кнопка «Поділитися»

- Викликає **Web Share API** з готовим текстом:

  ```
  Список бажань Марʼяни:

  📚 Книжка про дизайн — ₴450
  ✈️ Вихідні у Львові — ₴3 000
  ```

  Бажання без ціни — рядок лише з емодзі й назвою. Бажання з посиланням — URL додається в кінець рядка.
- На мобільному відкривається системне вікно шерингу.
- **Фолбек** (Web Share недоступний, типово desktop) — той самий текст копіюється в буфер обміну, кнопка на 2 секунди змінює підпис на «Скопійовано ✓», потім повертається. Тост не використовується.
- Якщо користувач закрив системне вікно без вибору — нічого не відбувається, повідомлення немає.
- **→ етап 2:** з появою серверної БД сюди додасться публічне посилання на список, і текст буде супроводжуватись URL.

### 4.3. Кнопка «Зберегти як картинку»

- Рендерить банер + картки в **PNG** і віддає файл: на desktop — завантаження, на mobile — системне вікно збереження/шерингу.
- Імʼя файлу: `wishlist-maryana.png` (транслітероване імʼя, нижній регістр).
- На картинці — банер і список бажань, без кнопок і без інтерфейсу застосунку. Фон — Canvas `#f5f5f5`.
- Під час генерації кнопка показує стан очікування й блокується від повторних кліків.
- Якщо генерація не вдалася — інлайн-повідомлення «Не вдалося створити картинку», кнопка повертається в норму.

### 4.4. Порожній стан

Якщо активних бажань немає (список порожній або всі здійснені):

- Банер показується, лічильник — «0 бажань».
- Замість карток — текст «Тут поки порожньо. Додай бажання, щоб було чим ділитися.»
- Обидві кнопки — **неактивні** (приглушені): ділитися й зберігати нічого.

## 5. Що свідомо не робимо на етапі 1

- Авторизація, акаунти, кілька користувачів — етап 2.
- Редагування створеного бажання (є лише видалення).
- Undo для видалення.
- Збереження чернетки форми.
- Публічне посилання на список.
- Сортування або пошук по списку — окрім фіксованого порядку «активні / здійснені, найновіші зверху».
- Синхронізація між пристроями, офлайн-режим понад те, що дає локальна БД.
