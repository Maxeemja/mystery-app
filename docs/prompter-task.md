# Завдання для промптера — Wishlist (інтерактивний прототип)

**Джерела істини:** [spec.md](spec.md) — продукт і модель даних · [interactions.md](interactions.md) — поведінка · [style-guide.md](style-guide.md) — дизайн-система Ui.
**Статус вхідних даних:** усі три документи апрувнуті, відкритих питань немає.

**Що на виході:** робочий інтерактивний прототип на 4 екрани — не статичні мокапи. Кліки працюють, дані зберігаються, перезавантаження нічого не втрачає.

---

## 1. Рамка

**Ітерація 1 — один користувач, локальне сховище, без авторизації.** Жодних логінів, паролів, серверних запитів. Усе живе в браузері.

**Але:** модель даних уже містить `userId` (завжди `local-user`) і `Profile.email` (порожній). Весь доступ до даних має йти через шар, що фільтрує за `userId` — навіть коли значення одне. Це не декоративна вимога: на етапі 2 зʼявиться авторизація (імʼя + імейл) і серверна БД, і перехід має бути **перенесенням даних, а не переписуванням**.

**Мова інтерфейсу:** українська. Усі тексти — з документів, не перекладати й не переписувати.

---

## 2. Модель даних

```
Wish {
  id: uuid
  userId: string        // завжди "local-user" на етапі 1
  title: string         // обов'язкове, до 60 символів
  emoji: string         // дефолт "🎁"
  image: blob | null    // альтернатива емодзі, взаємовиключні
  price: number | null  // цілі числа
  currency: "UAH" | "PLN" | "USD" | "EUR"   // дефолт UAH
  url: string | null
  isDone: boolean
  createdAt: datetime
}

Profile {
  userId: string        // "local-user"
  name: string          // 3–15 символів
  email: string         // порожнє, зарезервоване під етап 2
}
```

Персистентність — локальна БД браузера. Кожна зміна пишеться одразу, без кнопки «зберегти».

## 3. Дизайн-система

Повністю — в [style-guide.md](style-guide.md). Критичне:

| | |
|---|---|
| Шрифт | Geist (фолбек Inter). Заголовки 600, тексти 400/500 |
| Канва | `#f5f5f5` · Картки `#ffffff` · Текст `#0a0a0a` · Muted `#737373` · Бордер `#e5e5e5` |
| Радіуси | **Тільки 18px** (кнопки, інпути, беджі) або **24px** (картки). Нічого проміжного |
| Тіні | Тільки на картках. Кнопки, інпути, беджі — без тіней |
| Колір | Ember `#e7000b` — **виключно** видалення й помилки |
| Виняток | Confetti Amber `#f59e0b` — **тільки** банер на екрані «Поділитися», ніде більше |

Емодзі — Unicode-глиф системним шрифтом, не SVG і не картинка. Це принципово: гайд забороняє декоративну графіку, і трактування емодзі як тексту — те, що робить його допустимим.

**Анімації:** 150мс кросфейд · 200мс поява/зникнення · 300мс переміщення картки. `ease-out`. При `prefers-reduced-motion` — миттєво.

## 4. Тестові дані

Засівати при першому запуску (щоб екрани не були порожні):

| Емодзі | Назва | Ціна | Здійснене |
|---|---|---|---|
| 📚 | Книжка про дизайн | ₴450 | ні |
| ✈️ | Вихідні у Львові | ₴3 000 | ні |
| 🎧 | Навушники | ₴2 200 | **так** |

Профіль для демо: імʼя «Марʼяна».

## 5. Екрани

### 5.1. Init — знайомство

Показується один раз, поки в БД немає профілю.

**Вигляд:** мінімальний, по центру. Заголовок «Як тебе звати?» (Geist 600, 48px desktop / 30px mobile), одне поле, підказка, кнопка «Далі». Нічого більше — ні лого, ні навігації.

**Поведінка:**
- Автофокус на полі.
- Ввід обрізається на 15 символах (не приймає далі, а не показує помилку).
- `trim` перед перевіркою і збереженням.
- Підказка: `<3 символів` → «Ще мінімум N символів»; `3–15` → «Від 3 до 15 символів». Живого лічильника «N/15» немає.
- Кнопка неактивна, поки `trim(name).length < 3`. Реактивно на кожну клавішу.
- `Enter` = клік, якщо кнопка активна; інакше ігнорується мовчки.
- Збереження → перехід на «Мої бажання», fade. Назад повернутись неможливо.

### 5.2. «Мої бажання» — хаб

**Хедер:** імʼя користувача (клікабельне) · лічильник «3 бажання · 1 здійснене» · кнопки «Додати» (Filled) і «Поділитися» (Outline).

Лічильник **завжди показує загальну кількість**, незалежно від фільтра. Відмінювання коректне: 1 бажання / 3 бажання / 7 бажань (див. [spec.md 4.1](spec.md)).

**Фільтр:** три Badge — «Усі / Активні / Здійснені». Активний Solid, решта Outline. Скидається на «Усі» при кожному вході на екран і при перезавантаженні.

**Картка:** емодзі (або картинка) · назва · ціна `₴3 000` (пробіл-роздільник) · «Подивитися →» (нова вкладка, `rel="noopener noreferrer"`) · кнопка «✓» · іконка кошика (Ember).

Ціна й посилання показуються тільки якщо задані. Кнопки «✓» і кошик: **desktop — по hover** (fade 150мс), **mobile — завжди видимі**. Hover картки — легке підняття тіні, без зміни кольору.

**Порядок:** активні зверху, здійснені знизу, без розділювача. Усередині групи — найновіші зверху.

**Позначення «✓»:** іконка → Solid · картка тьмяніє (200мс) · переміщується в кінець плавним reflow (300мс) · лічильник оновлюється. Оборотно — повторний клік повертає на позицію за `createdAt`, не на попереднє місце. Якщо активний фільтр «Активні» — картка після анімації зникає зі списку. Без підтверджень і конфетті.

**Видалення — інлайн, не модалка:** клік по кошику заміщує вміст картки текстом «Видалити бажання?» + «Скасувати» (Outline) і «Видалити» (Ember). Габарити картки не змінюються, контент кросфейдиться. Одночасно активне лише одне підтвердження — відкриття на іншій картці закриває попереднє. `Esc` / клік поза карткою скасовує. Після видалення — fade + collapse, список переставляється без стрибка. Undo немає.

**Порожні стани — три різні:**

| Ситуація | Текст |
|---|---|
| 0 бажань загалом | «Поки що жодного бажання. Чого тобі хочеться?» + кнопка «Додати» |
| Фільтр «Активні», активних 0 | «Усі бажання здійснені 🎉» |
| Фільтр «Здійснені», здійснених 0 | «Ще жодне бажання не здійснене» |

У другому й третьому фільтр лишається видимим — щоб було зрозуміло, чому порожньо.

**Модалка зміни імені:** клік по імені → «Змінити імʼя», поле заповнене поточним значенням, автофокус із курсором у кінці, кнопка «Зберегти». Валідація ідентична Init. Закриття — клік поза, «×» або `Esc`.

**Повернення з «Додати»:** нова картка зверху групи активних, фон на ~900мс `#ffffff → #f5f5f5` і назад. Автоскрол до неї, якщо поза видимою областю.

### 5.3. «Додати» — форма

**Поля по порядку:**

1. **«Що це?»** — автофокус, обовʼязкове, до 60 символів, `trim`.
2. **Емодзі** — рядок з 8: `🎁 📚 ✈️ 🎧 👟 💻 🎮 ☕`. Вибраний — hairline-рамка (18px), без заливки. Повторний клік знімає вибір.
3. **«Або своя картинка»** — зона `dashed hairline`, radius 10px. Клік + drag&drop на desktop. До 5 МБ, JPEG/PNG/WebP/GIF. Прев'ю з «×». Стиснення до ~1200px перед записом. Помилки інлайн Ember: «Файл завеликий, максимум 5 МБ» / «Непідтримуваний формат».
4. **«Скільки коштує»** — тільки цифри, форматування пробілами на льоту (`3000` → `3 000`). Поруч select валюти: **UAH за замовчуванням**, PLN, USD, EUR. Нуль допустимий.
5. **«Посилання»** — плейсхолдер `https://…`. Протокол додається автоматично при збереженні. М'яка валідація: якщо явно не URL — Ember-підказка «Схоже, це не посилання», але **збереження не блокується**.

**Емодзі й картинка взаємовиключні:** завантаження картинки знімає емодзі, вибір емодзі прибирає картинку. Неактивний варіант приглушується. Якщо на момент збереження немає нічого — записується `🎁`.

**Кнопка «Додати бажання»:** неактивна, поки `trim(title)` порожній. `Enter` у будь-якому полі = клік. Повторні кліки під час збереження ігноруються.

**Скасування:** форма порожня → вихід одразу. Хоч одне поле заповнене → інлайн-підтвердження «Скасувати додавання? Введене не збережеться» + «Продовжити редагування» (Outline) / «Скасувати» (Ember). Те саме на `Esc` і кнопку «назад». Чернетка не зберігається.

### 5.4. «Поділитися»

**Банер:** Confetti Amber `#f59e0b`, radius 24px, текст `#0a0a0a`. Заголовок «Список бажань Марʼяни» (Geist 600, display 48px) + підпис-лічильник «2 бажання». Єдине місце в застосунку з цим кольором.

**Картки:** спрощені — емодзі, назва, ціна. Без «Подивитися», «✓», кошика. Некликабельні. **Здійснені не показуються взагалі** й не рахуються в лічильнику банера.

**«Поділитися»** — Web Share API з текстом:

```
Список бажань Марʼяни:

📚 Книжка про дизайн — ₴450
✈️ Вихідні у Львові — ₴3 000
```

Без ціни — тільки емодзі й назва. З посиланням — URL у кінці рядка. Фолбек на desktop: копіювання в буфер, кнопка на 2с змінює підпис на «Скопійовано ✓». Тостів немає. Закриття системного вікна без вибору — нічого не відбувається.

**«Зберегти як картинку»** — PNG з банером і списком, без кнопок і хрому застосунку, фон `#f5f5f5`. Файл `wishlist-maryana.png` (транслітерація, нижній регістр). Під час генерації кнопка в стані очікування й заблокована. Помилка → інлайн «Не вдалося створити картинку».

**Порожній стан** (активних бажань немає): банер лишається з «0 бажань», замість карток — «Тут поки порожньо. Додай бажання, щоб було чим ділитися.», **обидві кнопки неактивні**.

## 6. Глобальне

**Навігація:** «Мої бажання» — єдиний хаб. Init → список (незворотно). Список ↔ «Додати», список ↔ «Поділитися». Прямого переходу між «Додати» і «Поділитися» немає. Кнопка «←» вгорі зліва на обох підекранах; апаратна «назад» / свайп роблять те саме.

**Клавіатура:** `Enter` — підтвердити форму, якщо валідна · `Esc` — закрити модалку / скасувати інлайн-підтвердження · `Tab` — обхід у порядку читання · `Space`/`Enter` на «✓» — перемкнути. Фокус завжди видимий: hairline-ring `#e5e5e5`.

**Мобільна адаптація:** одна колонка карток замість сітки · кнопка «Додати» закріплена внизу екрана · «Поділитися» відкриває системне вікно · кнопки на картках видимі завжди (hover недоступний).

**Помилки сховища:** якщо локальна БД недоступна (приватний режим, вичерпана квота) — інлайн «Не вдалося зберегти» на місці дії. Застосунок не падає, зміна не застосовується.

## 7. Чек-лист приймання

Прототип готовий, коли всі пункти проходять уживу:

- [ ] Init приймає імʼя 3–15 символів, кнопка коректно блокується, більше не показується після збереження
- [ ] Бажання додається; нова картка зʼявляється зверху з підсвічуванням
- [ ] «✓» переміщує картку вниз і назад, лічильник оновлюється, відмінювання коректне
- [ ] Видалення працює через інлайн-підтвердження, скасування нічого не змінює
- [ ] Три різні порожні стани показуються в правильних ситуаціях
- [ ] Фільтр перемикає підмножину, лічильник не змінюється, при виході скидається на «Усі»
- [ ] Імʼя змінюється через модалку й підхоплюється на «Поділитися»
- [ ] Емодзі й картинка взаємовиключні; без вибору зберігається `🎁`
- [ ] Скасування заповненої форми питає підтвердження, порожньої — ні
- [ ] «Поділитися» шерить текст (mobile) або копіює в буфер (desktop)
- [ ] «Зберегти як картинку» віддає PNG
- [ ] Здійснені бажання не потрапляють на екран «Поділитися»
- [ ] **Перезавантаження сторінки зберігає всі бажання та імʼя**
- [ ] Мобільна версія: одна колонка, закріплена кнопка «Додати»

## 8. Чого не робити

- П'ятого екрана, налаштувань, онбордингу понад Init.
- Авторизації, логінів, серверних запитів — етап 2.
- Редагування створеного бажання, undo після видалення, збереження чернетки.
- Пошуку, довільного сортування, категорій, тегів.
- Кольорів поза палітрою: Ember тільки для видалення й помилок, Amber тільки для банера «Поділитися». Ніяких зелених «успіхів».
- Тіней на кнопках, беджах, інпутах.
- Ілюстрацій, фото, іконок-картинок. Емодзі — текст, не графіка.
- Радіусів, відмінних від 18px і 24px.
- Тостів і снекбарів — усі повідомлення інлайн, на місці дії.

## 9. Стек

Зафіксований, деталі — в [tech-stack.md](tech-stack.md). Стисло:

**Next.js (App Router) + React + TypeScript.** Сховище на етапі 1 — **IndexedDB**, не localStorage: картинки до 5 МБ не влазять у квоту localStorage і потребують base64. На етапі 2 — MongoDB через Server Actions.

**Важливо для генерації:**

- Server Components **не бачать IndexedDB**. Усе, що читає або пише дані, — клієнтські компоненти (`'use client'`). Серверними лишаються layout і статична оболонка.
- **Гідратація:** сервер рендерить без даних, клієнт довантажує з IndexedDB. Поки читання не завершене — **скелетон, не порожній стан**. Інакше при непорожньому списку блимне «Поки що жодного бажання».
- **Init-екран** не вирішується серверним редиректом — наявність профілю відома тільки клієнту.
- Доступ до даних — **лише через репозиторій** (`WishRepository`, `ProfileRepository`), компоненти не звертаються до IndexedDB напряму. `userId` передається в кожен виклик, навіть коли значення завжди `"local-user"`.
- Чиста логіка (валідація, відмінювання, форматування ціни, транслітерація) — в `lib/domain/`, без залежності від React і сховища.

**Бібліотечні потреби:** обгортка над IndexedDB, рендер DOM у PNG (`html-to-image` або аналог), Web Share з фолбеком на Clipboard API.
